# 커밋 규칙

P!ck My St☆r의 변경 이력을 읽고 검토하기 위한 규칙입니다.

## 메시지 형식

```text
<type>: <한국어로 작성한 변경 요약>
```

- 타입은 영문 소문자로 작성하고 콜론 뒤에 공백 한 칸을 넣습니다.
- 제목은 무엇을 변경했는지 구체적으로 적고 끝에 마침표를 붙이지 않습니다.
- `수정`, `업데이트`, `작업 완료`처럼 변경 내용을 알 수 없는 제목은 피합니다.
- 설명이 필요하면 제목 아래 한 줄을 비우고 변경 이유와 영향을 본문에 적습니다.
- 이슈 번호는 관련 이슈가 있을 때만 본문 또는 마지막 줄에 적습니다.

## 타입

| 타입       | 사용하는 경우                   | 예시                                                     |
| ---------- | ------------------------------- | -------------------------------------------------------- |
| `feat`     | 사용자 기능 추가·변경           | `feat: 포토부스를 개인 네컷 촬영으로 전환`               |
| `fix`      | 오류 수정                       | `fix: 한글 파일명 차이로 사진이 로딩되지 않는 문제 수정` |
| `style`    | 화면 스타일 또는 코드 포맷 변경 | `style: 강수 선택 표시의 이동 애니메이션 개선`           |
| `refactor` | 기능을 유지하며 코드 구조 개선  | `refactor: 이메일 전송 상태 관리 분리`                   |
| `docs`     | 문서 추가·수정                  | `docs: 커밋 메시지 작성 규칙 추가`                       |
| `test`     | 테스트 추가·수정                | `test: 개인 네컷 촬영과 초기화 검증 추가`                |
| `chore`    | 패키지·도구·설정 관리           | `chore: 개발 패키지 업데이트`                            |

사진·로고 등 화면에 사용하는 이미지 교체는 `style`로 작성합니다.
코드 포맷 변경과 화면 변경은 같은 타입을 사용하더라도 별도 커밋으로 나눕니다.
여러 타입이 섞이면 주요 목적을 기준으로 선택하되 독립적으로 검토할 수 있는 변경은 분리합니다.

## 변경을 나누는 기준

- 한 커밋에는 하나의 목적을 담습니다.
- 해당 기능의 코드·직접 관련된 테스트·안내 문구는 함께 커밋할 수 있습니다.
- 관련 없는 문서 정리·사진 교체·리팩터링을 기능 커밋에 섞지 않습니다.
- 아직 구현하지 않은 기능을 커밋 제목이나 PR에 완료했다고 쓰지 않습니다.
- 테스트 영상으로 확인한 것과 실제 웹캠·메일 발송으로 확인한 것을 구분합니다.

## 브랜치

`main`에서 직접 작업하지 않고 작업 목적에 맞는 브랜치를 사용합니다.

```text
feat/<기능명>
fix/<오류명>
style/<화면명>
docs/<문서명>
chore/<관리작업명>
```

현재 작업 브랜치는 `feat/solo-photobooth-sticker-timer`입니다.
브랜치 이름은 전체 작업 방향을 나타내며 모든 기능이 이미 구현되었다는 뜻은 아닙니다.

## 커밋 전 확인

```sh
git branch --show-current
git status --short
git diff
git diff --cached
git diff --check
```

1. 의도한 브랜치인지 확인합니다.
2. 변경 파일과 스테이징한 내용을 확인하고 관련 파일만 추가합니다.
3. `.env`, Google 앱 비밀번호, API 비밀키, `node_modules/`, `dist/`를 포함하지 않습니다.
4. 코드 변경은 필요한 타입 검사·빌드·테스트를 실행합니다. 문서만 변경했다면 문서 포맷·링크·내용을 확인합니다.

```sh
npm run typecheck
npm test
npm run build
npm run format:check
```

파일 추가 경로는 `git status`에서 확인한 실제 경로를 사용합니다.
문서 경로를 포함한 아래 명령은 `pickmystars` 폴더에서 실행하는 예시입니다.

```sh
git add COMMIT_CONVENTION.md
git commit -m "docs: 커밋 메시지 작성 규칙 추가"
```

커밋·푸시·PR 생성·배포는 각각 별도 작업입니다. 메시지 추천이나 문서 작성만 요청한 경우 실행한 것으로 간주하지 않습니다.

## 현재 작업 범위와 후속 작업

- 현재 수정: 아이돌 합성을 제거하고 개인 네컷 촬영으로 전환
- 후속 작업: 사용자가 제공한 Y2K 참고 이미지에서 흰 배경을 제거한 개별 스티커 준비 및 붙이기
- 후속 작업: 스티커 꾸미기에 180초 제한 적용

스티커 준비·붙이기와 180초 제한은 사용자가 구현을 요청한 뒤 진행합니다.
현재 커밋 규칙 작성 단계에서는 기능이나 스티커 이미지를 추가하지 않습니다.
